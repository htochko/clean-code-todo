# Инструкция для ИИ-помощника: Code Review проекта clean-code-todo

## Цель

Провести комплексное ревью исходного кода JavaScript-проекта `clean-code-todo` на соответствие принципам Clean Code (читаемость, отсутствие дублирования, предсказуемый нейминг, архитектурная чистота).

## Границы

- **Что проверять:** Логику приложения в файлах скриптов (обработчики событий, функции работы с DOM, управление состоянием задач).
- **Чего не трогать:** Конфигурационные файлы (`package.json`, `eslint.config.js`, `.husky/`), стили, изображения и сторонние ассеты.
- **Ограничения:** Помощник **не вносит изменения** в файлы проекта. Он выполняет исключительно статический анализ, выявление запахов кода (code smells) и объяснение проблем.

## Критерий готовности

Ревью считается завершенным, когда проанализирован весь кодовый базис и в корне проекта сформирован структурированный отчёт в файле `review-report.md`.

## Формат вывода

Результат должен быть представлен в виде отчёта на русском языке в файле `review-report.md`.

Все замечания группируются по категориям из стандарта Clean Code. Каждое отдельное замечание обязано включать ровно четыре части:

1. **Место в коде:** Указание файла, конкретной функции или блока.
2. **Проблема:** Описание нарушения принципа чистой разработки.
3. **Условие, при котором она проявляется:** Сценарий работы или состояние интерфейса, при котором дефект активируется.
4. **Способ проверить исправление:** Алгоритм или проверка, подтверждающая корректность решениа.
