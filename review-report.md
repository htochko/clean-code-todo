# Отчёт о код-ревью (Code Review Report)

Ниже приведены замечания по результатам анализа файла `app.js`, сгруппированные по категориям принципов Clean Code.

---

## Категория: Readability & Meaningful Names (Читаемость и выразительные имена)

### 1. Использование магического индекса для поиска ключевой кнопки

1. **Место в коде:** файл `app.js`, инициализация переменной `addButton` (`const addButton = document.getElementsByTagName('button')[0];`).
2. **Проблема:** Получение главной кнопки интерфейса по порядковому индексу тега в DOM (`[0]`) является хрупким подходом, нарушающим принципы самодокументируемого кода и читаемости.
3. **Условие, при котором она проявляется:** Если в HTML-разметку перед основной формой добавления задачи будет добавлена любая другая кнопка (например, кнопка переключения темы или авторизации), индекс `0` укажет не на ту кнопку, и функционал добавления задач перестанет работать.
4. **Способ проверить исправление:** Добавить тестовую кнопку в разметку перед кнопкой добавления задач, заменить поиск по индексу на поиск по селектору/id (например, `document.getElementById('add-btn')`) и убедиться, что клик по кнопке добавления стабильно создает новую задачу.

## Категория: Consistency & Standards (Согласованность и стандарты кода)

### 2. Смешивание подходов привязки событий (`addEventListener` и свойства `onclick`)

1. **Место в коде:** файл `app.js`, функции `bindTaskEvents` (`editButton.onclick = editTask;`, `deleteButton.onclick = deleteTask;`, `checkBox.onchange = handleTaskStateChange;`) и привязка `addButton.addEventListener('click', addTask);`.
2. **Проблема:** В коде одновременно используются современный метод `addEventListener` и устаревшее свойство `.onclick`. Присваивание через `.onclick` перезаписывает предыдущие обработчики без предупреждения, что противоречит стандартам безопасного написания кода.
3. **Условие, при котором она проявляется:** Если в процессе масштабирования приложения потребуется повесить второй независимый обработчик события на кнопку удаления или редактирования задачи, старый обработчик будет тихо перезаписан и стерт.
4. **Способ проверить исправление:** Переписать привязку всех событий (`editButton`, `deleteButton`, `checkBox`) на использование исключительно метода `addEventListener` и проверить работоспособность интерфейса при добавлении, редактировании и удалении задач.

## Категория: Architecture & Encapsulation (Архитектурная чистота и инкапсуляция)

### 3. Жесткая и хрупкая навигация по структуре DOM через `parentNode`

1. **Место в коде:** файл `app.js`, функции `editTask`, `deleteTask` и `handleTaskStateChange` (везде используется `const listItem = this.parentNode;`).
2. **Проблема:** Логика управления элементами жестко завязана на предположение, что непосредственным родителем целевых элементов управления является тег `li`. Это нарушает инкапсуляцию и повышает связанность (coupling) кода с конкретной разметкой.
3. **Условие, при котором она проявляется:** При изменении стилей или структуры HTML-разметки (например, если обернуть элементы задачи внутрь дополнительного контейнера `div` для улучшения верстки), `this.parentNode` вернет этот `div` вместо `li`, что приведет к падению скрипта и ошибкам при вызове методов управления задачей.
4. **Способ проверить исправление:** Заменить прямое обращение `this.parentNode` на поиск ближайшего элемента списка с помощью метода поиска предка по селектору (`this.closest('li')`), изменить разметку, добавив промежуточную обертку, и убедиться, что удаление и редактирование задач выполняются без ошибок.
